> （见 [`bookconv优化白皮书.md`](bookconv优化白皮书.md)），也不讲模块怎么拼（见

## 1｜一张图看懂

![两条线总览](diagrams/spec-overview.svg)

书架里的书有两种来源：**已有的 EPUB**（走"优化线"：清洗、整理），和**有文字层的 PDF**（走"转换线"：
把 PDF 拆成字和图，按原版面重新排成 EPUB）。两条线最后都要过同一道**质量门**：过了才替换原书，不过就
原样退回、原书一个字节不动。两条线也都要迁就同一个阅读器 xochitl——它有不少"脾气"（第 3 章），规范里
大部分规则都是为了绕开这些脾气定下的。

## 2｜三条底线（任何规则都不能违反）

1. **不改动书的内容**。文字一个不多一个不少，图片还是那张图，作者的强调（颜色、加粗）要保留。能做的只是
   "排版适配"：让字号字体可调、边距合适、目录可用、图片不溢出。（2026-09-20 用户对 PDF 线明确过"不允许
   变动书籍内容"；2026-09-23 再次明确"字体颜色、链接、图片位置不能更改"。）
2. **真机验证才算数**。xochitl 不开源，行为经常出人意料，电脑上的单元测试只能证明代码逻辑对，证明不了
   阅读器里看起来对。改了规则要么在设备上看，要么用第 7 章的"免肉眼"方法量。
3. **拿不准就保守**。宁可不处理，也不冒把书弄坏的风险。例：判断不出 PDF 有没有文字层，就只裁边不转换
   （转换后原 PDF 只在隐藏备份里留 7 天，出错代价远大于"这本没转"）。

## 3｜xochitl 的脾气：十条实测规则

> 这些都是真机反复踩出来的，不是凭文档推测。**"规范允许"不等于"xochitl 能用"**——我们迁就阅读器的
> 实际行为，而不是 EPUB 规范文本。

**样式类（1–7）**——决定了所有排版规则只能写进外链 CSS 文件（EPUB 线是 `cangjie-wash.css`，PDF 线是
`pdf-img.css`），而且写法要"朴素"：

| # | 规则 | 后果/对策 |
|---|---|---|
| 1 | **只认外链 `.css` 文件**，不认 `<style>` 块、不认 `style=""` 属性 | 规则一律写外链文件；颜色、图宽也只能用 class |
| 2 | `!important` 无效 | 不能靠它压过书自带样式 |
| 3 | 单个元素、单个 class、"元素名+class"（如 `p.cj-tx`）都可靠；逗号并列 `.a, .b` 未复核，保守不写 | 一条规则一个选择器；要压过书自带的类规则时用"元素名+class"（漫画混排页 `p.cj-tx` 真机坐实，bookconv 白皮书 §20） |
| 4 | 同优先级"先出现者胜"（与标准相反） | 多份 CSS 改同一选择器时注意顺序 |
| 5 | 值为 `0` 会被当"没设" | "不缩进"写 `0.01em` |
| 6 | `text-indent` 会被子元素继承 | 顶格段落要剥掉继承来源的 class |
| 7 | 规则里最后一条声明缺分号会被丢 | 输出的每条声明都带分号 |

**跳转类（8–10）**——2026-09-23 用测试书 + 真书实验坐实：

![xochitl 链接规则](diagrams/spec-xochitl-links.svg)

| # | 规则 | 后果/对策 |
|---|---|---|
| 8 | **正文链接只有"同一个文件内的 `#锚点`"会跳**；跨文件（`chap_0002.xhtml#x`、`./…`、不带 `#` 的都算）一律被当外部网址 | 需要书内跳转时，链接和目标必须在同一个文件（PDF 线的"单文件模式"就是为此） |
| 9 | **目录（nav）支持文件内锚点**，能精确定位到页 | 单文件书的目录可以指向 `chap_0001.xhtml#pdf-p22` |
| 10 | **跳转目标必须是有内容的元素**（`<p id>`、`<div id>`、`<h2 id>`）；空元素 `<a id="x"></a>` 不会被登记，指向它的链接点了没反应 | 锚点 id 挂在段落上，不用空 `<a>`。注意：目录不受此限，所以"目录能跳"不代表"正文链接能跳" |

**文件合法性**：OPF 只要不是合法 XML（哪怕书名里混进一个 `\0` 字符），**整本书只渲染出 1 页**，日志里也
看不出原因（只有 `Asked for unknown item ""`）。质量门专门拦这一条（第 6 章）。

## 4｜EPUB 优化线的规则

> **大白话**：书自带的样式里，"锁死字号字体"和"背景图"这类妨碍阅读的拿掉，作者的强调留下，再把注释、
> 目录、封面、图片整理成 xochitl 能正常用的样子。

### 4.1 样式：拿掉什么、保留什么

![样式取舍](diagrams/spec-css-policy.svg)

样式表、`<style>` 块、`style=""` 三处都按同一张表处理（`bookconv/src/cssunlock.rs`，2026-09-29 移植自 sheng-ren）：

| 声明 | 处理 |
|---|---|
| `font-family` | 去掉，字体交给阅读器 |
| `font-size` | 绝对大小（`px`、`pt`、`medium` 这类）去掉；相对大小（`em`、`%`、`smaller`）保留，标题、小字、上标的层次跟着设备字号一起缩放。例外：作用在正文整体上的（`body`、`html`，不带类的 `p`、`div`），相对大小也去掉，否则设备上设的字号不是正文的实际字号 |
| `font` 简写 | 拆开：字体、字号、行高去掉，粗体、斜体、小型大写保留 |
| `line-height` | 去掉（写死的行高让设备的行距设置不起作用） |
| `background` 简写 | 只留颜色，背景图去掉（xochitl 不认 `no-repeat`，会把背景图平铺满页盖住正文，《飘》） |
| `background-image` | 去掉（同上） |
| 用 `vh` 写的高度 | 去掉（占满一屏的书名页加上页眉页脚会溢出成空白页） |

- **保留**：颜色（含灰色）、粗体、斜体、对齐、背景色等其余样式。加粗和彩色字通常是作者的强调，拿掉会丢信息（2026-09-17 定）。
  2026-09-29 起**不再把灰字提成纯黑、细字提到 400**——那是改颜色和字重，不是解锁（用户定，两条线一起停，见第 8 章 T2）。
- 段落上下间距清零、左右保留；`body/html` 边距清零。样式表开头的 `@import`、`@charset` 原样保留；`@font-face` 不动。
- **例外**：
  - **注释容器**（选择器含 `footnote`/`fnote`，如多看的 `duokan-footnote-item`、我们自建的 `.footnotes`/
    `.cj-fnote`）：去掉加粗，字号 `0.85em`（比正文小一号，五号→小五；随设置缩放）。模板里的加粗是装饰不是强调，
    《甲午》真机反馈"全书注释永远加粗"（2026-09-23 用户拍板）。
  - **首行缩进统一**：中文 `2em`（标题后第一段照常缩进）、西文 `1.2em`（标题后第一段顶格，换成 `<div class="cj-flush">`，
    写了 `text-indent` 的书自带类从它上面去掉、其余强调类保留）；两端对齐；西文另加自动断字、避免孤行寡行（单独一条 CSS）。
    中文段首用来缩进的全角空格、`&nbsp;` 去掉，缩进统一由 CSS 给（xochitl 会把段首 U+3000 折叠掉）——这是唯一会去掉的字符。
  - **居中、居右**：`align=` 属性或行内样式写的，换成 `cj-center` / `cj-right` 类（xochitl 不认行内样式，类规则优先级高于 `p{}`）。
  - `<html>` 缺 `lang` 的补上（取 OPF `dc:language`，没有就按正文字符分布判）。

### 4.2 注释（脚注/尾注）

- 默认"锚点模式"：注释集中到章末，正文标记是同章 `<a href="#注释id">`，点了跳过去，xochitl 的"返回"浮标
  （已延长到 20 秒）点回原处。弹窗注释做不到（阅读器不支持），"固定在页面底部"也做不到（流式排版没有
  固定的页）。不写 `epub:type="noteref"`（sheng-ren 给 KOReader 另出的"弹窗模式"`FootnoteMode::Popup` 代码移植了，
  母版库不用；当年设备上 KOReader 与 xochitl 读同一份文件时也以 xochitl 为准）。
- **标号原样保留，只有图的标号换成上标数字**：有文字的标号（上标、数字）不动，前后一个字不加（2026-09-29 起不再在标号后加 `[N]`）。
  **只有图、没有文字的标号**（多看的小图标等）换成上标数字——2026-09-29 真机《注释探针》坐实：xochitl 里**只有图的链接点了没反应**
  （80/32/24/16 像素、带不带 `<sup>` 都一样，链接里有文字才能跳；目标是 `<li>` 也能跳），图标还按原图像素画，外链 CSS 的
  `height:1em` 限不住（《甲午》80×80 图标撑成一大块，与 v8《飘》同一结论）。用户在"上标数字 / `[N]` / 小图标 + 数字"里选了上标数字。
  编号取目标注释开头作者写的编号（`[14]`、`【14】`、`14.`、`14、`，必须带括号或标点，免得把"1886年"当编号），其次图标 alt 里的
  "注释N"，都没有才按本章顺序数。认法：`duokan-footnote` 类（在图或外层链接上）；或同文件链接里只有图、且链接/图带注释类或目标元素
  有注释语义（`number_icon_note_links`，也管重优化 v16 产物——那时 `duokan-footnote` 类已被剥掉）。真书《甲午》84 个图标标号全部换成 `14`、`15`……
- 每条注释带 `cj-note` 类（`page-break-inside:avoid`），一条注释不拆到两页（长过一页的照常断开）。
- 只搬**被引用、而且带注释语义**（`class`、`epub:type`、`type` 里有 note）的注释块；目录页、导航文档里的链接不算引用，
  也不往这些页里搬。注释按（所在文件, id）区分，两个文件里同名的 `id="n1"` 不会互相覆盖。搬之前核对每条都有章节接收，
  没人接的留在原处。
- 注释容器一律用 `<div id>`，不用 `<p id>`：注释原文里本身可能有 `<p>`，套进 `<p>` 会变成非法嵌套。
  （`<div id>` 有内容，也满足规则 10。）
- **重优化旧产物**：母版库的「优化」是原地覆盖，v15 及以前优化过的书已经没有原件。再优化时，旧版在原标号后面追加的
  `<a href="#f">[N]</a>`（前面紧挨着指向同一锚点的原标号）会去掉；旧版把图标整个换成 `[N]` 的，原图标已不在标号里，不动。

### 4.3 目录与封面

- **目录**：书没有目录才自动生成（按 h1–h6；纯图片书每 20 页一段）；"第 X 部 编号 章名"式扁平目录重建成
  两级；NCX 在清单里的 id 必须叫 `ncx`（xochitl 写死了）；`dtb:uid` 与书的标识同步；剥掉外部 DTD 引用。
- **书名与目录文字只转义一次**：从书里读出的标题、书名是转义过的 XML 文本（`&amp;`、`&#12288;`），先还原成字符，
  写回 NCX/nav/OPF 时再统一转义一次。此前没还原就再转义，目录和设备显示名里出现字面的 `&amp;`（2026-09-25）。
  自动目录、"第X部"重建、大文件占位的书名都遵守这条（超限分卷的书名与目录当时也遵守，分卷 2026-09-30 已移除）。
- **目录指错位置的改指**：条目目标处的文字不是以条目标题开头才算指错，而且只改能核实的（书里有标题完全相同、只有一处的链接或
  `<h1>`–`<h6>`，或锚点在文件末尾、下一个文件开头就是这个标题）；核实不了、有歧义的不动（《占星术杀人魔法》NCX 整体错位）。
- 书的目录不叫 `nav.xhtml`、但 OPF 里标了 `properties="nav"` 的，也算有目录。书自带目录**全是一级**、里面有"第X部"时按部重建成两级；
  已分好层级的不动。标题是"名字 + 编号"（`第一章 1`）时自动目录拆成章、节两级。
- **封面**：OPF 里要同时有 `<meta name="cover">` 和 `properties="cover-image"`，且指向真实图片；缺了就从
  第一页找图补上。书里一张图都没有时联网补（4.9）。封面页是一个 `<svg>` 里包一张 `<image>`（整页只有这张图、没有文字）的，
  换成 `<img>`；页面上还有别的内容、SVG 里有文字的都不动。

### 4.4 图片与漫画

- 普通插图：放进 842×1455 的竖框，也就是默认页边距下的真实可阅读范围（宽绝不超过 842，防止横幅溢出），只缩不放，已达标的不重新编码。
  2026-09-30 从屏幕尺寸 954×1696 收小，对齐 sheng-ren：默认页边距下插图本来就只显示 842 宽，多出的像素只占体积（测试书插图小 13%–25%）；
  页边距调到 28 档时栏宽 898，插图会被阅读器放大约 7%。
- 产物里的图片不压缩（zip STORED），其余条目 deflate（2026-09-30 对齐 sheng-ren；此前图片用 deflate 最快档，多压 6%）。
- 漫画（图 ≥20 张且每图平均文字 <40 字）：一次解码、裁白边（单边最多 35%）、一次缩放、补白到页框、一次
  编码，画质损失只有一代。漫画页一律 JPEG 质量 95，包括低分辨率小 JPEG 预放大后的页（2026-09-30 用户定，与 sheng-ren
  一致；此前放大页用 85 控体积）。代价是低分辨率漫画明显变大：2026-09-20 做 PDF 时实测《镖人》卷 02 q85 约 71MB、q95 约 113MB，
  EPUB 产物没量过。
- 超过 900 万像素的图原样保留不处理（设备内存实测上限；sheng-ren 在电脑上已放开到 6400 万像素，设备只有 2GB 内存，**不移植**）。
- **JPEG 无损瘦身**（2026-09-29 移植）：每张重新编码的 JPEG 把哈夫曼表按这张图重做，量化后的图像数据一个不动，解码逐像素相同；
  每页还会把新旧两份解码比对，有一点不同就用原来的（`bookconv/src/jpegopt.rs`）。测试漫画 114.5→107.3MB。
- **漫画里的静态 GIF、WebP 页**：GIF 转 PNG，WebP 有损的转 JPEG、无损的转 PNG；条目名不变，OPF manifest 的 `media-type` 跟着改
  （改名要改遍全书引用、容易漏）。动图原样保留；只在本来就要改像素时才换格式。带透明通道的漫画页先铺白底（此前透明处会变黑）。
- 漫画的 OPF 加 `<dc:subject>漫画</dc:subject>`（已有不加），给阅读器和书架自己认漫画用。
- **重优化旧产物不再多一代有损**：书里带着本优化器的标记时，已经按同一页框排好的漫画页原样保留（宽不超过 954、高不超过页框、
  长宽比在容差内、不是还能预放大的小 JPEG；最小边距的旧画布 954×1458 也算）；换了页框（实验室开关切换）的照常重排。测试漫画 196 张重优化后逐字节不变。
- **不再有"超限按卷拆分"和"漫画转 PDF"**：2026-09-30 两者都已移除（代码一并删除）。超过网页上传上限的书只走"占位 + 磁盘替换"，
  走不了就整本拒绝（传书线架构 §6）；漫画一律产出 EPUB。
- **漫画页边距最小化**（网页「管理→实验室」开关，默认关）：开着时漫画图排进 952×1457 的画布（页边距 1 时 xochitl 的图片框，
  sheng-ren 2026-09-29 读 xochitl 排出的 PDF 实测；2026-09-30 之前是按 302.4:462.1 算的 954×1458，差 1–2px）、
  首次打开时把阅读器页边距设成 1，左右留白从约 20pt 降到 1pt 以内；纯文字页和图文混排页的文字另留 17.8pt 边
  （9 条留边规则整套写进样式表，不看书里有没有这类页，与 sheng-ren 一致）。
  关着时一切照旧（补白到屏幕比例 954:1696）。
- 一张图具体怎么分流（文字书、漫画、超大图）有图见 `bookconv优化白皮书.md` §05；实现细节与真机数据见 §05、§20。

### 4.5 其它清洗

- **DRM**：只加密了字体的"伪 DRM"直接剥掉；正文被加密的真 DRM 报错拒绝，原书不动。
- **空页**：没有文字也没有图的页删掉，目录改指下一页。有 `<body>` 却没有 `</body>` 的**截断页**按 `<body>` 之后的全部内容判断
  （2026-09-30；此前当成空页整页删掉，有文字的截断页会丢）。
- **死引用**：指向不存在文件的 `<img>`（没有有意义替代文字的）和 `@font-face` 删掉。
- **同一标签两个 id**：先合并成一个（非法 XHTML 会让 xochitl 整章不显示，《消失的爱人》真机踩过）。
- **全书 id 去重**：跨文件重复的 id 改名，全书指向它的链接一起改（分页之后做）。
- **只靠 `<br>` 换行的文件**：全文件没有一个 `<p>`、至少 4 个 `<br>`、每段都是完整行内内容的，按 `<br>` 分成 `<p>`，首行缩进才有地方加；
  有一处拿不准，整个文件不动。
- **章尾空白页**：删掉每个文件末尾没有可见内容的空段落和换行（被链接指到的保留）；包住文件结尾的容器去掉下边距、下内边距和"之后分页"。
- **远程图**：抓到的内联进书、并补进 OPF manifest；抓不到的 `<img>` **删掉**（xochitl 离线时画巨大的破图占位，与 sheng-ren 的"原样保留"
  有意不同）。抓到的图和本地插图同一规则：缩进 842×1455 竖框（4.4）；**超过 20MB 的整张不要**，按"抓不到"处理（`netimg::MAX_IMAGE_BYTES`）。
  2026-09-30 修：此前远程图按整页屏幕框缩，横幅能到 1696 宽，违反"插图宽不超 842"；抓网文的图还会缩两遍、JPEG 多损一代；
  超过 20MB 的图此前被截断成残图写进书里。抓网文生成的书同样适用。
- **没有扩展名的章节文件**：按内容识别（文件开头是 `<?xml`/`<html`），不按扩展名——EPUB 规范认 OPF 里的
  类型声明、不认扩展名。此前《甲午》29 章里 4 章被整体漏洗。

### 4.6 阅读方向（只保留原书自带的，2026-09-30）

> **大白话**：日漫是从右往左翻的。书里有个标记告诉阅读器这一点；「优化」原样保留这个标记，不加、不改、不删。

- **现行规则**：OPF `<spine>` 上的 `page-progression-direction` 原书写什么产物就是什么（底线 1）。书架不替书判断方向：
  漫画识别只看得出"是漫画"，看不出"是日漫"，国漫、美漫从左往右，自动设 rtl 会把它们翻反（底线 3）。
- **生效范围**：xochitl 的日漫翻页规则按"OPF 写了 rtl，或 uuid 在旧手动清单 `rtl-overrides.json` 里"判定（系统增强线白皮书 §03i）。
  这份清单现在只读：book-serve 不再写，已有条目照旧生效，要撤就手动删文件或删条目。
- **历史**：2026-09-25～09-29 母版库可以按书手动指定方向（自动 / 从右往左 / 从左往右），「优化」时写进 OPF，已优化过的书
  只改 OPF、其余条目原样拷贝；加入过 xochitl 的书同时把 uuid 写进/移出手动清单。当时不升 `OPTIMIZE_VERSION`，因为不设方向时
  产物逐字节不变（T4）。**2026-09-30 用户定整个撤掉**，写入函数一并删除。当时设过方向、又点过「优化」的书，方向已经写在
  OPF 里，照样生效；已进清单的 uuid 继续生效；其余不做迁移。

### 4.7 章节分页（2026-09-29 移植自 sheng-ren）

![章节分页](diagrams/spec-paginate.svg)

**章标题独立一页；节标题和正文同页；节与节之间、节与章之间都分页。** 做法是按标题把章节文件拆成多个文件——xochitl 里每个
spine 文件从新的一页开始；不用 CSS `page-break-*`（xochitl 认不认从没验证过，见 T3 第 2 条）。漫画、目录页不拆；拆过的书再处理不再拆。

- **哪一级是章、哪一级是节**：看全书实际用到的 `<h1>`–`<h6>`。最浅一级是章（最浅一级是"第X部/卷"、全书只出现一次或下一级多是"第X章"时，
  下一级也算章）；紧跟章标题、中间没有正文的那一级是副标题，和章标题同页；再下一级是节，新起一页；更深的不分页。
- 全书没有 `<hN>` 时按目录找标题：目录指向的短段落（≤60 字），锚点可以在段落上，也可以是它前面紧挨着的空元素。
- 好读式结构：目录指到的"第一章"只是一段字时当章标题；全书没有节一级标题时，独占一段、从 1 严格连续编号、每节都有 ≥50 字正文的
  数字段落当节标题；和章同级、只写节号的标题（`<h3>２</h3>`）至少两章都这样时降成节。
- 拆开后：全书指向被拆文件的链接（正文、目录、NCX、OPF）改指到目标所在那一份；切点处没闭合的外层元素前一份补闭合、后一份重新打开；
  注释块搬到引用它的那一份末尾（xochitl 只认同文件锚点，规则 8）；没有文字的份、只剩标题的份、章标题后不到 30 字的尾巴并回前一份。
- 书自带目录漏了节时按阅读顺序补进去（比所属的章低一级，只补和章标题同一个原文件里的节）；已有的平排节条目缩进到所属章下面。
- **笔记线**：`notes/crates/epubmap` 按 spine 文件的起始页把勾画归章。拆出来的份多数没有自己的目录条目，2026-09-29 起这些页归到前面最近一个
  在目录里的文件那一章（Calibre 按大小切的 `index_split_NNN` 同样受益）。
- OPF 用 `opf:` 前缀写的（`<opf:itemref>`）也照样登记：拆出的第 2 份起按原书的写法插进 spine、manifest（2026-09-30 修；此前只认无前缀的
  `<itemref>`，这类书拆出来的后半章进不了 spine，在阅读器里消失）。NCX 的 manifest id 改名时 `<opf:spine toc>` 同步改。
- （历史）KOReader 在时曾发现它的「避免章末空白页」会把拆开的文件又连成一片、H1–H3 前换页会把副标题和章标题分到两页；
  2026-09-29 KOReader 从设备卸载，此项不再跟进。

### 4.8 规范整理：一律升级到 EPUB 3（2026-09-29 移植）

清洗的最后一步（`wash/normalize.rs`），文字书和漫画都做。只改格式，可见文字不动：

- **OPF**：`version="3.0"`；补 `dcterms:modified`（固定值 `2000-01-01T00:00:00Z`，产物逐字节确定）；`unique-identifier` 保证指向有内容的
  `<dc:identifier>`（`<opf:package>` 前缀写法也认，2026-09-30 修：此前取不到会把 `unique-identifier` 删掉）；缺 `dc:language` 按书的语言补；EPUB 2 的 `opf:role/file-as/scheme` 改写成 `<meta refines>`。`<meta name="cover">`、`<guide>` 保留。
- **目录**：`toc.ncx` 和 `<spine toc="ncx">` **保留**（xochitl 找目录靠 manifest 里 id 为 `ncx` 的 NCX），`dtb:uid` 升级后再对齐一次。没有 nav 的
  按 NCX 生成 `nav.xhtml`；只有 nav 的按 nav 生成 NCX。`<guide>` 同时写成 nav 里的 `landmarks`（`hidden`）。
- **manifest `properties`**：按最终内容标 `svg`/`mathml`/`scripted`/`remote-resources`（OPF 最后写进 zip）。
- **XHTML 修成合法 XML**：DOCTYPE 换成 `<!DOCTYPE html>`；HTML 命名实体换数字引用；裸 `&`、`<` 转义；XML 不允许的控制字符去掉；空元素自闭合、
  属性补引号；根元素补 `xmlns`/`xmlns:epub`；多余闭合标签**只在去掉后整份配平时**才去。
- 实测（2026-09-29，本机 28 本文字书 + 1 卷漫画，sheng-ren `tools/regress/compare.py`）：可见文字与改动前逐本一致（《金庸全集》少一个原书里的
  损坏字符 U+0010，预期），不合法 XML 39 → 0。**EPUB 3 在 xochitl 上还没真机验证**：书能打开、目录入口在且层级对、封面缩略图、注释跳转与返回、
  `<!DOCTYPE html>` 的章节不白屏、`hidden` 的 landmarks 不当正文显示。

### 4.9 书里没有封面就联网补（2026-09-29 移植自 sheng-ren）

母版库「优化」EPUB 前，书里没有有效的封面声明、前几页也没有图时，book-serve 联网找一张（`book-serve/src/cover_fetch/`），只在 OPF 里声明成
封面图（`bookconv::opfmeta::edit_epub`：不加封面页、正文不变），再走优化。回执末尾写明补了哪张、或为什么没补。

1. **豆瓣**：按书名（书里的 `dc:title` 与母版库文件名两路，繁简、全半角、括号说明都规整后比）和作者找条目，前几个对得上的里挑分辨率最高、
   像封面的图（够大、竖版）。图片服务器要带来源页。设备直连可用（2026-09-29 实测取到《白夜行》封面）。
2. 豆瓣没有时找**原作**：Wikidata 作品 → Open Library → Wikimedia Commons。⚠ 设备在国内网络直连不了这几个网站，这一步通常很快以"连不上"跳过。
3. 都没有：**生成**一张（书名在上、作者头像或作者名首字居中、作者名在下，样式按书名哈希挑，同一本书每次一样；字体用设备上的
   Noto Sans CJK SC / 霞鹜文楷，`SHELF_COVER_FONT` 可指定）。
- **没查成不生成**：豆瓣那一步遇到网络错误（离线、重试完超时、强制门户返回网页而不是 JSON）就整个放弃，这次不补，下次优化再试——
  生成的封面会写进母版，写进去以后就不会再找真封面了。
- 超时与重试按设备收紧（单个请求 12 秒、最多试 2 次，连不上的网站之后直接跳过），不让一本书的优化卡几分钟。

## 5｜PDF→EPUB 转换线的规则

> **大白话**：把 PDF 拆成一个个字（带位置、字号、颜色）、一张张图（带位置、大小）、一个个链接，再按原来
> 的版面顺序重新排成段落。目标是：字一个不差、颜色一样、图在原来的位置并保持原来的大小比例、链接能点。

![PDF→EPUB 六步](diagrams/spec-pdf2epub-pipeline.svg)

适用范围：**有文字层**的 PDF（每页平均能抽出 ≥40 个字）。扫描件和漫画 PDF 只裁白边、仍是 PDF。转换成功
且过了质量门后，以 `<书名>.epub` 留在母版库，原 PDF 挪进母版库下的隐藏目录 `.pdf-originals/` 保留 7 天（2026-09-24 起；此前直接删除）。母版库已有同名 `<书名>.epub` 时停下报错，不覆盖。

### 5.1 文字：一个字都不能多、不能少

![文字拼接规则](diagrams/spec-text-flow.svg)

- **空格**：同一行里只在两个字之间真有缝隙时补空格（缝隙按真实字宽算，要乘页面缩放、加字间距）；中文接
  中文不补；折行处补一个空格，但中文接中文、行尾是连字符或斜杠时不补（复合词、网址不被截断）。
- **分段**：三条线索满足一条就换段——行距明显大于本页典型行距、上一行是短行（离右边界还差 4 个字宽以上）、
  上下两行字号明显不同。一句话跨 PDF 页边界时接回同一段。
- **不变量**：文字层每个字按顺序进正文，公式框里的字也不删；只把正文里原有的标题段落升级成 `<h2>`，找不到
  就不加，不往正文里塞原书没有的字。
- **书名**按 PDF 规范解码（`FE FF` 开头是 UTF-16BE）。此前一律当 UTF-8，T.E. 的书名解出一串 `\0`，整本只
  渲染 1 页。书名所在的 `/Info` 和 `/Title` 是间接对象或内嵌字典时也要认出来（2026-09-25；此前取不到，退回用文件名）。

### 5.2 颜色

- 每个字的填充色都取出来（灰度、RGB、CMYK；认不出的颜色空间如专色、图案，当"不确定"不填色——宁缺勿错）。
- 纯黑和"不确定"不加标记，按黑字显示；其它颜色（2026-09-29 起含灰色，与 EPUB 线一起不再提黑，第 8 章 T2）用 `<span class="cj-cN">`，全书同色共用一个 class，规则写进
  `pdf-img.css`（规则 1：xochitl 不认内联样式）。颜色变了才换 span，不是每个字包一层。
- 实测：手册的红色警告、Word 蓝色网址；T.E. 的经济学人红、链接蓝、灰色日期按原色保留。

### 5.3 图片：位置和大小跟着原书走

![图片落位与缩放](diagrams/spec-image-placement.svg)

- **位置**：插在"图片上沿以上最近的那一行字"之后。不能按绘制顺序——Word 导出的 PDF 每页先画完所有文字、
  最后才画图，按顺序会把图全堆到页尾，甚至插进一句话中间（手册第 1 页二维码真机坐实）。
- **并排**：插在同一处、上沿相差不到 8pt 的几张图放进同一段并排（原书并排的二维码/截图）。
- **大小**：宽度 = 图在 PDF 上的宽度 ÷ 正文栏宽，取 5% 一档（`.cj-w45{width:45%;height:auto}`），跨栏大图
  封顶 100%，栏宽算不出就维持原像素大小。栏宽取全书字符左右边缘的 2%–98% 分位，排除页码等零星位置。
- 图片文件后缀按实际编码定（JPEG 用 `.jpg`），`src` 路径与压缩包里的真实位置一致——两者任一错了图都不显示
  （手册二维码曾因此消失）。
- **图片解码**：`DCTDecode`（JPEG）原样透传、不重编码；`FlateDecode` 的 8 位灰度/RGB 解成像素再编 PNG。`ICCBased`、`CalGray`、`CalRGB`
  按解出的字节数认 1 通道还是 3 通道；滤镜链里夹着 `DCTDecode`（如 `[FlateDecode DCTDecode]`）的先解外层再当 JPEG。2026-09-30 修：
  此前单通道 ICC 图被当 RGB、编码失败，转出的 EPUB **静默丢图**；`[Flate DCT]` 链被当裸 JPEG 透传成坏图。

### 5.4 链接与"单文件模式"

- PDF 里的链接（`Link` 注释：外部网址、书内跳转，以及各种写法的跳转目标）都转成 `<a href>`：链接矩形框住的
  字包进去，颜色 span 在里层。外部网址原样保留（xochitl 没有浏览器，点了打不开，但不删，底线 1）。
- **书内跳转**：目标页第一个有内容的段落挂 `id="pdf-pN"`（规则 10：不能用空元素）。
- **单文件模式**：只要有一个书内跳转跨了章，整本书合成一个 XHTML 文件，目录的每一条改指
  `chap_0001.xhtml#pdf-pN`（规则 8、9）。没有跨章跳转的书维持"一章一个文件"。
- 实测 T.E.：344 个链接全部解析到目标，95 个目标逐个核对落在原书对应内容所在页；用户在设备上点击验证通过。

### 5.5 切章：每页只进一章、一页不丢

![切章规则](diagrams/spec-chapter-partition.svg)

- 章节来源优先级：PDF 书签 → 按字号认标题 → 每 20 页一段（如实标"第 N 部分"，不伪造标题）。
- 往回指的书签当分组标题（只进目录、不占页）；多条书签同页，内容归最后一条；第一条书签之前的页并入第一章。
- 此前的切法让 T.E. 内容重复约 10 倍（604 万字 vs 原书 50 万），渲染检查预估 4978 页；现在 600 页左右。

### 5.6 为什么 fork 了 pdf-extract

抽字用的第三方库 `pdf-extract` 0.12.1 满足不了"颜色/图片位置"，还有几处错误。我们在
`shelf/crates/pdf-extract-cj/`（MIT 许可，保留原作者版权）里只改了五处，字体解码这类最难、最容易出错的
部分原样保留：

1. 补上六个最常用的颜色指令（`g/G/rg/RG/k/K`，原库完全没处理）；
2. 把每个字的颜色传出来；
3. 图片不再被当成"子页面"错误解析，改为报告图片位置；
4. 修正中文字体宽度表"区间写法"的解析（原库三处全错，中文字宽全为 0）；
5. 嵌套表单（Form XObject）最多展开 16 层、同一对象不重复展开（2026-09-24）：自引用的表单以前能把 book-serve
   的栈打爆，整个进程崩掉，`catch_unwind` 也接不住。
6. 页内容和嵌套流的解压设上限（单页合计 64MB，`MAX_PAGE_CONTENT_BYTES`；2026-09-24 页内容，09-30 扩到嵌套流），常见的损坏 PDF panic
   改成返回错误；
7. 沿 `/Parent` 往上找继承属性（`get_inherited`）改成最多 64 层的循环（2026-09-30）：`/Parent` 成环时此前无限递归栈溢出。

逐条说明在 `pdf-extract-cj/src/lib.rs` 开头的注释里。

### 5.7 损坏或恶意的 PDF：宁可不转，不能拖垮服务（2026-09-30）

PDF 是用户上传的任意文件，处理它的 book-serve 同时管着整个母版库。规则是：**坏 PDF 只能让这一本转不了，不能让进程崩、内存爆**。
栈溢出（SIGSEGV）不是 panic，`catch_unwind` 接不住，整个 book-serve 会倒；所以递归和解压必须事先设上限：

| 情况 | 处理 |
|---|---|
| `/Parent` 指回自己或绕成环 | 找 MediaBox、资源等继承属性最多走 64 层（bookconv `classify::get_inherited_media_box` 与 pdf-extract-cj `get_inherited` 两处），走满按"没有"处理 |
| 解压炸弹（几 KB 压缩流解出几 GB） | 页内容与嵌套流合计 64MB 封顶；图片 Flate 流按声明的宽 × 高 × 3 字节封顶；PDF 加载时单条流 64MB 封顶 |
| 抽字时第三方代码 panic | 分类按"判不准"处理，当成**无文字层**（底线 3），不让整次优化报错 |
| 文字层里只有 `\0` 占位字 | 不算文字（分类与"仅裁边"闸门同一口径 `visible_char_count`）；此前分类把它算成文字，可能判成"有文字层"去转换 |
| 大文件通道读第三方 PDF 页数 | 页数必须来自 `/Type /Pages` 字典，读字典对象最多 4MB（此前对象 2 是 `/Outlines` 时把书签数当页数） |

这些都只在开发机用构造的坏文件测过（`pdf_ingest/tests.rs`），未部署、未上真机。

## 6｜质量门：替换原书前的最后一道检查

优化或转换写出新文件后、替换原书之前自动运行；**任何一条"拦截"触发，原书一个字节都不动**。

![质量门：新文件先写到临时文件，过门才替换原书](diagrams/spec-quality-gate.svg)

适用范围：EPUB 优化、PDF 转 EPUB，两条都过这道门（2026-09-25～09-29 还有"只改阅读方向的轻量改写"，已移除）。"PDF 仅裁边"的产物还是 PDF，不过这道门；
它靠"只处理零文字、每页恰一张整页图的 PDF，否则拒绝"兜底（第 5 章开头）。

| 检查 | 结果 | 为什么 |
|---|---|---|
| 真 DRM（正文被加密） | 拦截 | xochitl 打不开 |
| 目录链接命中率 < 80% | 拦截 | 目录大面积失效 |
| 同一标签两个 id | 拦截 | 非法 XHTML，xochitl 整章不显示 |
| 图片/样式等资源引用命中率 < 80% | 拦截 | 图不显示（手册二维码事故） |
| OPF 不是合法 XML | 拦截 | xochitl 整本只渲染 1 页（T.E. 事故） |
| 正文某章不是合法 XML | 提醒 | 那一章可能不显示；原书本来就这样，拦了也换不来更好的结果 |
| 没有目录 / 目录锚点丢失 / 只混淆了字体 | 提醒 | 可读，但体验打折 |

"OPF 合法"这条上线前，对设备书库 56 本真实 EPUB 扫过：只有两份出事的 T.E. 不合格，零误伤。

## 7｜怎么验证（不用逐页肉眼看）

| 想确认的事 | 方法 |
|---|---|
| 书能不能完整渲染 | 投递后看母版库"渲染检查"的页数；或读设备上 `<uuid>.content` 的 `pageCount` |
| 版面、图片、颜色 | xochitl 为每本 EPUB 生成预览 PDF `<uuid>.pdf`，拉回电脑渲染成图片看 |
| **正文链接能不能跳** | 读预览 PDF 的"跳转目标表"（catalog `/Dests` 名字树）：每个链接的目标名都要在表里；再比对目标页的文字 |
| 目录跳到哪页 | 读 `<uuid>.epubindex`（Qt 二进制：UTF-16 的 `文件#锚点` + 页码） |
| 文字有没有丢/多 | 正文去空白后的字符数与 `pdftotext` 对比（我们保留行尾真实连字符，pdftotext 会删） |
| XML 合不合法 | 用严格 XML 解析器过 OPF 和每章 |

⚠ 2026-09-23 的教训：曾经只用 `.epubindex`（目录）去核对正文链接，得出"能跳"，结果用户一点不跳——
两套机制不同，正文链接必须看跳转目标表。

## 8｜取舍记录

**T1（已决，2026-09-23）注释加粗 vs "保留原书加粗"**
《甲午》的注释模板写死了加粗，全书注释都是粗体。决议：只去掉注释容器的加粗、注释小一档，正文加粗不动。
理由：注释模板的加粗是装饰，正文加粗是强调，"保留加粗"要保护的是强调。

**T2（2026-09-29 改决）灰字要不要提黑**
此前 EPUB 线把无彩色灰字提成纯黑（墨水屏上浅灰难读），PDF 线按"颜色不能更改"保留原灰色，两线不一致。
决议（用户选"PDF 线也提黑"）：两条线统一——无彩色的灰字按黑字显示，彩色字一律保留。理由：墨水屏上
浅灰字的可读性损失大于"灰"这个颜色本身承载的信息；真正表达强调的是彩色，彩色不动。
**2026-09-29 改为两条线都不提黑**：用户要求以 sheng-ren 为参照移植文字处理规则，那边 09-29 定"只解锁字体字号行高、不动别的样式"——
把灰字改黑、细字提重是改颜色和字重，不是解锁；阅读器自己有对比度、字重设置。两条线仍然统一，只是统一到"保留原色"。
代价：浅灰细字在墨水屏上偏淡，真机看着吃力时再议。

**T3（已调研，结论：不做；2026-09-25）书里自带的"目录页"跨文件链接**
设备书库扫描（09-23）：7 本 EPUB 的书内目录页共 335 个链接是跨文件的（每章一个文件），在 xochitl 里点不动
（规则 8）；这些书用 xochitl 自己的目录菜单都能正常跳（规则 9）。09-25 曾考虑做成"按书可选开关、默认关"，
先调研了能不能在不合并文件的前提下让这些链接能跳：

| 方案 | 能不能跳 | 为什么 |
|---|---|---|
| 只改 href 写法（`./c3.xhtml#x`、补 `#`、改相对/绝对路径） | 不能 | 规则 8 实验已穷举这些写法，跨文件一律当外链 |
| 在目标章里补锚点（非空元素挂 id） | 不能 | 目标挂没挂锚点不是问题，链接和目标不在同一文件才是 |
| 把各章开头复制进目录页、改成同文件锚点 | 能跳，但不可取 | 往书里塞原书没有的内容（底线 1），且跳到的是副本不是正文 |
| 把目录页复制进每一章 | 同上 | 同上 |
| **目录页 + 全部正文合成一个文件** | 能 | PDF 线的"单文件模式"就是这样（第 5.4 节，T.E. 约 600 页、344 个链接用户点过） |

所以唯一有效的做法是整书合并。它对 PDF 线可行，是因为那些 EPUB 是我们自己排的：全书一份 CSS、`<body>` 不带类、
"章"本来就是人为切的。换到第三方 EPUB，风险逐条如下：

1. **样式会变，而且事先算不准**：各章 `<head>` 引的 CSS、`<body class>` 常常不同（Calibre 每章 `calibre1/2/…`），
   合并后只能留一个 `<body>`，章自己的 body 类只能降级成 `<div>`，`body.x{}` 这类规则就失效；而 xochitl 规则 4
   "同优先级先出现者胜"让多份 CSS 叠加的结果依赖顺序；body 类在 xochitl 上确实影响版面（bookconv 白皮书 §09⑩：
   页边距 1 时 Calibre body 类吃掉约 20pt）。违反底线 3（拿不准就保守）。
2. **章与章之间不再换页**：xochitl 里每个 spine 文件从新的一页开始；合并后要靠 `page-break-before` 之类的 CSS 换页，
   而 xochitl 认不认这类属性从没验证过（各白皮书无记录）。PDF 线单文件模式本来就是逐页接排，不需要换页，所以没踩到。
3. **笔记线的"按章归类"会整本失效**：笔记线 `notes/crates/epubmap` 用 `.epubindex` 里**每个 spine 文件的起始页**把
   勾画的页号映射到章（`BookMap::chapter_of`：页 → spine 文件 → 目录里 `file` 相同的第一条）。合成单文件后全书只有
   一个 spine 文件，所有勾画都会被标成第 1 章，"按章生成笔记本"随之失效——跨线回归，要一起改 epubmap 才能做。
4. **路径与锚点改写面很大**：各章可能在不同目录，图片/CSS 相对路径要逐个改基准；全书所有跨章链接（不止目录页）、
   nav/ncx 每一条都要改成 `单文件#锚点`，锚点还得挂在非空元素上（规则 10）。id 去重已有（`dedup_ids_in_chapter`），
   但这是一整套新的改写逻辑，出错就是整本跳转失效。
5. **大书渲染未验证**：单文件模式只在约 600 页的 T.E. 上验证过；小说常见 1–2MB 正文、上千页，单个 XHTML 的导入
   渲染耗时与内存没有数据。
6. **已加入的书要重投、阅读进度对不上**：结构变了，xochitl 里旧副本的进度与批注不会迁移。

收益一侧：只是"书内目录页那一页能点"，而目录菜单本来就能用。**结论：不值得做，不实现开关。** 真要做，前提是
先在设备上验证第 2 条（xochitl 认不认 CSS 换页）并改好第 3 条（epubmap 支持文件内锚点映射），再逐本对比第 1 条
的版面。

**T4（已决，2026-09-25；2026-09-30 改定）阅读方向：不自动判，现只保留原书自带的**
见第 4.6 节。自动判"日漫"没有可靠依据（漫画识别分不出日漫与国漫/美漫），翻反比不翻更糟。09-25 定的是"只手动、不升版本号"
（不设方向时产物逐字节不变，升版只会让整库无故变"旧版"）；09-30 用户定连手动指定也撤掉，优化只保留原书的方向，版本号同样不动。

**已排除的风险**：担心 calibre 书常用空 `<a id>` 当注释目标会跳不动（规则 10）——扫描书库 36 本，同文件
链接指向空目标的为 0。
