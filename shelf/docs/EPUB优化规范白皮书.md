# EPUB 优化与 PDF→EPUB 转换规范白皮书

> **这是什么**：这是一份**规范类**文档——回答"能不能这样改/这条规则对不对"，不是架构史、也不是踩坑流水账。
> 架构（模块怎么拼起来）见 `传书EPUB线架构.md`；引擎实现细节与踩坑时间线见 `bookconv优化白皮书.md`；
> 这份文档只收**当前生效的规则 + 为什么这么定 + 出处**，规则变了就地改，不留"历史版本"堆积。
> 覆盖两条共享同一份规范的线：**① EPUB 优化**（`bookconv::wash`/`optimize`，清洗已有 EPUB）、
> **② PDF 文字层→EPUB 转换**（`bookconv::pdf_ingest`，从无到有生成 EPUB）。

## 00｜起源

2026-09-23，用户提问："我们已经处理过很多 EPUB 书籍了，能否据此结合 EPUB 官方规范制定一套我们自己的
行之有效的 EPUB 优化及文字 PDF 转 EPUB 规范？" ——本项目此前的规则散落在两份工程白皮书的历次决策节点里
（`bookconv优化白皮书.md` 按时间顺序记"发现了什么"，`reMarkable书架白皮书.md` §03q/§03y/§03av 记具体
决策），没有一份文档回答"当前到底该怎么做"。本文档是那次讨论的落地产物。

## 01｜总纲：三条不可违反的底线

1. **不改动书籍原有内容**——文字、图片本身、颜色、加粗语义不能因为"优化"而变化，能做的只是排版适配
   （字号解锁、边距归一、目录补全这类）。2026-09-20 用户对 PDF→EPUB 线明确过这条（不允许丢字/加字），
   2026-09-23 对 EPUB 优化线的注释样式决策再次确认了同一条底线的适用边界（见 §06 T1）。
2. **真机验证再宣称完成**——xochitl 渲染器闭源、行为多次与直觉/host 单测不符（`text-indent:0` 被当没设、
   `!important` 不生效这类）。规则改动光过 host 单测不算数，要么真机看、要么走内部预览法（`book-serve`
   走 loopback 投递、量设备生成的 `<uuid>.pdf` 侧车文件，免去肉眼盯屏幕）。
3. **判不准时选保守分支**——宁可不转换/不裁剪，也不冒把书搞坏的风险。例：PDF 分类器 `classify_pdf`
   判不准（解析失败/形状不像三类中任何一类）一律退到 `NoTextLayer`（只裁边，不转 EPUB）——转 EPUB 是
   破坏性格式变更，出错代价远高于"这本书没转成"。

## 02｜与 EPUB 官方规范的关系

- 官方规范：OCF/zip 容器 + OPF manifest/spine + XHTML content documents；**文件扩展名不是权威依据**，
  manifest 里的 `media-type` 声明才是。真实 EPUB 允许章节文件完全没有扩展名，只要 manifest 正确声明。
  本项目此前 `is_html()` 纯按扩展名判断，会整体漏过这类章节——落地为 `is_html_entry()`：扩展名优先，
  无扩展名文件才退到内容嗅探（首 200 字节找 `<?xml`/`<!doctype html`/`<html`）。2026-09-23 真机《甲午：
  摇摆的战争》29 章里有 4 章是这种形态，此前被清洗流程整体跳过（字体锁死、脚注问题都没被处理到）。
- xochitl 对官方规范的实现不完整（见 §03）——这些不是我们违反规范，是渲染器本身没有完整实现规范，
  清洗层的职责是**迁就渲染器的真实行为**，不是迁就规范文本。

## 03｜xochitl 渲染引擎实测规则（十条，真机坐实）

1. CSS **只认外链** `.css` 文件，不认内联 `<style>` 块、不认 `style=""` 属性——排版规则一律写外链
   `cangjie-wash.css`，内联注入在 xochitl 上从未生效（v10 起改外链，此前版本的"注入了但没变化"都是
   这个根因）。
2. `!important` 无效——不能靠它压过书自带样式的优先级。
3. 类选择器**认**，但**复合/逗号联合选择器不可靠**——只信任裸的单元素/单类选择器（`p{}`、
   `.footnote{}`），`.a, .b{}` 或 `p.foo{}` 这类不保证生效。
4. **同优先级下"先出现者胜"**——不是标准 CSS 级联规则（标准是后出现者胜），是 xochitl 自己的实现，
   两份外链 css 都改同一选择器时顺序要注意。
5. 值为 `0`（含 `0em`/`0.0pt`）会被当"没设"处理——`text-indent:0` 想要的"不缩进"效果实际不生效，
   要写 `0.01em` 这类非零但视觉等效的值，配合专门的 flush 类。
6. `text-indent` 会被子元素继承——顶格段落（如标题后紧跟的英文首段）需要专门剥掉继承来源的类，
   不能只在自己身上清零。
7. **规则内最后一条声明缺尾分号会被整条丢弃**——`.calibre_{...;margin:0}` 若 `margin:0` 没有尾分号，
   这条声明本身会连带丢失。清洗层输出的每条声明一律带尾分号。
8. **只有同一个文件内的 `#锚点` 是书内跳转**——跨文件链接不管写成 `chap_0002.xhtml`、
   `chap_0002.xhtml#x` 还是 `./chap_0002.xhtml#x`，一律被当成外部网址（预览 PDF 里是 `/URI` 动作），
   点了不跳。2026-09-23 真机实验：投一本 3 章测试书、量 xochitl 生成的 `<uuid>.pdf` 链接注释坐实。
   KOReader 不受此限。
9. **目录（nav）支持文件内锚点，并精确定位到页**——同一实验的单文件版：`.epubindex`（Qt 二进制，
   UTF-16BE 路径 + u32 页号）里 `chap_0001.xhtml#c3` 映射到第 7 页、中段锚点 `#t3` 映射到第 10 页，
   与预览 PDF 实际位置一致。所以"需要书内跳转"的书可以合成单文件、目录改指文件内锚点。
10. **跳转目标必须挂在有内容的元素上**——空元素（`<a id="x"></a>`）上的 id 不进 xochitl 的跳转目标表，
   指向它的链接点了没反应；目录不受影响（目录走 `.epubindex`，空元素也能定位），所以只验证目录会漏掉。
   2026-09-23 真机：《T.E.双语》用空 `<a id>` 时预览 PDF 具名目标 0 个、用户点目录页链接不跳；改挂到
   页首段落 `<p id>` 后 95 个全部登记、逐个核对跳转页正确。判别法：读预览 PDF catalog 的 `/Dests`
   名字树条数。待查：calibre 转出的书常用空 `<a id>` 当注释目标，同样可能跳不动。
   另：OPF 只要不是合法 XML（哪怕只是 `dc:title` 里一个 `\0`），整本书只渲染出 1 页。

## 04｜EPUB 优化线（wash）规则

### 04.1 字体/颜色/加粗——§03av 原则 + 注释容器例外

- **解锁** `font-size`/`font-family`（`DEFAULT_FILTER_PROPS` 剥除，允许用户切换全局阅读字体/字号）；
  **保留**原书 `color`/`font-weight`——正文里的加粗通常是语义强调（书名号、人名、关键词），不是排版
  瑕疵，剥掉会丢信息（2026-09-17 定案）。
- **例外（2026-09-23 定案）**：选择器命中"注释容器类"（`is_footnote_container_selector`：选择器文本
  含 `footnote`/`fnote`，不分大小写，覆盖书自带的 `duokan-footnote-item` 等和本项目自建的
  `.footnotes`/`.cj-fnote`）——**只剥这类选择器的 `font-weight`，不碰正文**；注释容器字号固定比正文
  小一档（`FOOTNOTE_FONT_SIZE = "0.9em"`，相对单位，随用户当前字号缩放）。理由见 §06 T1：注释模板的
  加粗是原书排版套版决定的装饰样式，不是语义强调，和正文场景不是同一件事，不违反上一条原则的精神。
  没有书自带注释 CSS 时，`cangjie-wash.css` 补两条兜底：`.footnotes{font-size:0.9em;}` /
  `.cj-fnote{font-size:0.9em;}`。

### 04.2 边距/段距

- `body`/`html`/`@page` 的 `margin`/`padding` 整个删除。
- 含 `p`/`div` 的选择器与内联 `style`：上下 `margin`/`padding` 归零、左右保留（`keep_para_spacing`
  开关可退回全保留）。

### 04.3 脚注

- 下载态（`inline_footnotes`）与优化器态（`preserve_relink_footnotes`）是两条独立代码路径，行为不完全
  对称，改动要分别测。
- 容器统一用 `<div id="frag">...</div>`，不用 `<p id="frag">...</p>`——源内容本身可能已含 `<p>`
  （如 `<aside><p>...</p></aside>` 这类结构），用 `<p>` 包会产出非法的 `<p><p>...</p></p>` 嵌套。
- 行内图标类 marker（如书自带 `duokan-footnote` class，可能标在 `<img>` 或外层 `<a>` 上，两处都要判）
  按固有像素尺寸渲染会被撑得巨大——一律丢弃图标，只留 `[N]` 文字链接。

### 04.4 无扩展名章节文件

见 §02——`is_html_entry` 已接入 `wash`/`optimize`/`check` 全流程调用点，不要有遗漏（新增调用点记得
统一用这个函数而不是历史的纯扩展名 `is_html`）。

### 04.5 质量门 `check.rs`

- 真 DRM（非伪 DRM 的 `encryption.xml`）、目录 href 命中率 <80%、单标签双 id → **硬失败**。
- **正文资源引用命中率 <80% → 硬失败**（2026-09-23 新增）：扫全部 `is_html_entry` 命中的正文文件里
  `src=`/`href=` 引用（跳过 `http(s)://`/`data:`/`mailto:`），解析相对路径后核对 zip 里是否真有这个
  文件。EPUB 优化线与 PDF→EPUB 线共用同一条检查（`check_epub_file` 用 `epubzip::read_skeleton`，图片
  字节留空只读骨架，避免整本读入内存）。
- 已接入 `book-serve` 真机优化流程：检查在 `produce_then_replace` 闭包内、写完产物之后、改名替换之前
  跑，**检查失败时原文件完全不动**（不是"优化出坏文件"，是"优化被拒绝、退回原样"）。

## 05｜PDF 文字层→EPUB 转换线规则

### 05.1 图片与颜色：自研 content-stream 解释器精确还原（2026-09-23 起，取代早期"不碰=不改"的消极策略）

**背景**：最早版本对"不改颜色/不挪图片位置"的实现是消极的——文字提取根本不取颜色、图片按页整批
提取后堆在段末，"不改"只是"没有主动改"，不是真的还原了原书颜色和图片精确位置。用户在《移动互联
软件安装使用手册》/《2026-09-19 T.E.双语》两本真实技术手册上要求按原格式（颜色/连接/图片位置）
生成 EPUB 后，坐实这条线需要真正精确的颜色 + 图片位置，不能再靠"不做"糊弄过去。技术上卡在依赖
`pdf-extract` 0.12.1 的公开 API：`OutputDev::output_character` 根本不传颜色（虽然它内部
`GraphicsState.fill_color` 有跟踪）、`Do` 算子对所有 XObject（含图片）一律当 Form 递归解析（图片
字节被当 content stream 走，逻辑性错误）、且连它自己内部的颜色算子处理都不全（`g`/`G`/`rg`/`RG`/
`k`/`K` 六个直接颜色算子完全不处理，只处理 `sc`/`scn`）。

**决议**（用户拍板"颜色/精确位置一起换成自研解释器"）：不重写字体/glyph 解码（pdf-extract 这部分
成熟、真正难、容易在 CJK/嵌入字体边界出错），只 fork 它、在 `Processor::process_stream` 里扩展三处：
补全六个颜色算子、`output_character` 新增颜色参数、`Do` 按 `/Subtype` 区分图片（新增
`output_image(ctm, xobject_name)` 钩子，不再错误递归）。落地在本地 crate
`shelf/crates/pdf-extract-cj/`（MIT 协议，vendored fork，见该 crate `src/lib.rs` 头注释），bookconv
通过 Cargo `package =` 重命名机制透明接入，调用方代码里仍是 `pdf_extract::`，无需改调用点。

- **颜色**：`PositionedChar` 新增 `color: Option<[u8;3]>`（解析不出的 colorspace，如 Pattern/
  Separation/DeviceN/Lab，返回 `None`——"不确定"当默认色处理，不瞎猜，见 `resolve_fill_rgb` 头注释）。
  纯黑（`[0,0,0]`）跟 `None` 一样不包 span（默认字色已经是黑）。**颜色只能用外链 CSS class**——
  §03 规则 1 说过 xochitl 不认内联 `style=`，`optimize_pdf_to_epub` 收集全书去重后的颜色表，生成
  `.cj-cN{color:#rrggbb;}` 规则拼进 `assemble_pdf_derived` 的共享样式表（跟 `img{max-width}` 那条
  同一份文件），色变才关/开 `<span class="cj-cN">`，不是每个字符都包一层。
- **图片事件**：`ImageEvent{seq, ctm, xobject_name}`，`xobject_name`（`Do` 引用的资源名如 `Im1`）用
  `page_image_ids()` 反查对象 id 后复用 `decode_pdf_image_to_bytes` 解码；`ctm` 给出图片在页面上的矩形
  （视觉定位与缩放都靠它，见下两条）。
- 图片文件后缀与 `media-type` 必须按字节内容嗅探一致（`image_ext_and_media_type`：SOI 魔数 `FF D8`
  判 JPEG 否则按 PNG），不能按解码分支硬编码——后缀与实际编码对不上时，真机渲染器可能按后缀走快速
  解码路径，读不出真实编码会导致图片整个不显示（2026-09-23《手册》真机坐实）。
- 图片相对路径必须与实际 zip 层级一致：本模块章节文件与 `images/` 同级（都在 `OEBPS/` 下），`src`
  不能带 `../`，带了会多跳一层指向不存在的路径（同一次真机排查发现的第二个根因）。
- **图片位置按视觉坐标，不按绘制顺序**：Word 导出的 PDF 每页先画完所有文字、最后才画图片（《移动
  互联软件安装使用手册》真机坐实），按 `seq` 排会把图全堆到页尾。现行：图片插在"它上沿以上最近的
  一行文字"之后（`image_visual_pos`）；同一插入点、上沿相差不到 8pt 的图片放进同一段落并排
  （`image_rows`，原书并排的二维码/截图不再上下叠放）。calibre 导出的 PDF 绘制顺序本来就与视觉一致，
  结果不变。
- **图片尺寸按原书比例**（2026-09-23 用户要求"图片可适当缩放，保障显示效果与原 PDF 基本一致"）：
  图片在 PDF 上的绘制宽度 ÷ 全书正文栏宽（字符左/右边缘 2%–98% 分位）→ 5% 一档的外链 class
  `.cj-wN{width:N%;height:auto;}`；栏宽算不出就不缩放。
- **链接**：页面 `/Annots` 的 `Link` 注释（`/A /URI`、`/A /GoTo /D`、`/Dest` 显式数组/具名目标均支持），
  矩形内的字符包进 `<a href>`（`<a>` 在外、颜色 span 在里，空白字符不单独开合）。书内跳转的目标 id 挂在目标页
  第一个有内容的段落上（`<p id="pdf-pN">`，升级成章标题时跟到 `<h2>`，见 §03 规则 10）；因 §03 规则 8，**有跨章书内跳转的书合成单文件**，目录条目改指
  `chap_0001.xhtml#pdf-pN`（规则 9）；没有的维持多文件。《T.E.双语》实测：预览 PDF 里书内跳转从
  3 个变成 454 个。
- **已知局限**：`page_image_ids` 不处理继承自父页面节点的 `/Resources`（查不到就跳过这张图）；颜色
  解析对 Pattern/Separation/DeviceN/Lab 保守放弃；外部网址链接在 xochitl 上点了打不开（设备无浏览器），
  只是保留原样。

### 05.2 内容不变

- 每个字符都进文字流，包括公式外接框内的——不允许因为"这里有公式"就把框内文字整体丢弃
  （2026-09-19 真机样本坐实：丢框内字符会连带吞掉紧贴公式的正文单词）。
- **字间不许凭空加空格**：`pdf-extract` 的 `line` 是定位次数不是视觉行，逐字定位的排版（calibre）每个字
  `line` 都不同——换行只看基线 `y` 是否真的变了；字号/字宽要乘文本矩阵×CTM 缩放、计入字间距 `Tc`；
  中文接中文、行尾连字符/斜杠接下一行都不补空格。此前《T.E.双语》标题被拆成"C a n  t h e"（约 500 处）。
- **分段**三条线索任一成立才换段：行距 > 本页典型行距×1.3、上一行离右边界还差 4 个字宽以上（短行）、
  上下两行字号明显不同；一句话跨 PDF 页边界时接回同一段（`join_pages`）。
- fork 修正：CID 字体 `/W` 区间写法解析全错导致中文字宽为 0（`pdf-extract-cj` 头注释④）；PDF 文本
  字符串（标题等）按规范解码 UTF-16BE/UTF-8/PDFDocEncoding（此前一律当 UTF-8，产出 `\0`）。
- 标题处理只做"正文中原有的标题段落原地升级成 `<h2>`"，找不到匹配就不加——不额外插入原书没有的文字，
  也不允许同一标题在章内出现两次。

### 05.3 章节切分

TOC 优先（PDF 书签）→ 没有书签按字号识别标题 → 都识别不出来才按固定页数分块（这种情况如实标注
"第 N 部分"，不伪造 `<h2>` 标题）。**每页只进一章、一页不丢**（`partition_chapters`）：往回指的书签
（calibre 导出的杂志，一级栏目书签全指向目录页）当分组标题、起点顺延；多个条目同页时内容归最后一个；
第一个条目之前的页并入第一章。此前按"本条到下一条"取范围，《T.E.双语》内容重复十倍（604 万字符 vs
原书 50 万）。分组标题只进目录、不再生成空白章节文件（`Book.nav` 显式目录）。

## 06｜已决张力记录

### T1（已决，2026-09-23）：注释容器加粗 vs "保留原书加粗"原则

- **冲突**：§03av"解锁字号但保留原书颜色/加粗"这条原则，字面上会保护《甲午：摇摆的战争》里
  `duokan-footnote-item{font-weight:bold}` 这条书自带样式；但真机反馈是"全书注释永远加粗、看不清"，
  追下去发现用户感知到的"字体不对"其实是"加粗"，不是字体本身变了。
- **决议**（用户明确拍板）：只剥注释容器类选择器的 `font-weight`，不碰正文；注释容器字号固定比正文
  小一档，用相对单位。
- **理由**：注释容器的粗体是原书模板写死的装饰样式，不是像正文加粗那样承载语义强调——两者虽然都叫
  "加粗"，但保留的价值不同，缩小规则适用范围不违反原则本身要保护的东西（语义信息不丢失）。
