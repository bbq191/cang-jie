# 《书名》- 总结卡片（B 模型实际生成格式）

> 这是 `wr-stars-daemon` **真机实际生成**的卡片结构（已端到端验证）。每本有 ★ 待办的书对应一份
> 可编辑笔记本，命名 `《书名》- 总结卡片`。daemon 每次画星后重生成：**你用 Text 工具打的字全部保留**，
> 只更新「本书待办」区的 ★ 行。手写笔迹不保（读不回，会被重建抹掉）——**要留的批注请用 Text 工具打字**。

---

## daemon 生成的卡片长这样

**每个有 ★ 的页 = 卡片里独立的一张页**（一主题一卡，留整页给你打字），每页套同一套 2.md 结构，
最后一张是自由区。EPUB 书自动带**章名**（读 `.epubindex` 页→spine + `.epub` toc）：

```
第 1 张卡片页（书名 + 待办区头 + 第一处 ★）:
  《赎罪》- 总结卡片

  ━━ ★ 本书待办 ━━
  ★ 洋娃娃 · 第 8 页          ← 章名自动填（第8页属"洋娃娃"章）
  [ID: 洋娃娃-p8]             ← 供跨页软链接检索的唯一 ID
  〔线索框〕
  🔵 时间节点：               ← 你用 Text 工具在冒号后打字，重建时逐字保留
  🔴 核心实体：
  🟢 案件代号：
  〔逻辑推演网〕
  　
  〔标签与锚点〕
  🔖 Tags：
  🟡 金句：
  🔗 指向 → ID：

第 2 张卡片页（第二处 ★，同结构）:
  ★ 洋娃娃 · 第 9 页
  [ID: 洋娃娃-p9]
  〔线索框〕…（同上）
```

> 一星一页、每页同结构，**无自由区页**。擦掉某颗 ★ → 该卡片页连同你在上面打的字一起消失
> （star = 待办本身，擦星即完成）。开书不会重复生成，每本书恒 1 张卡。

## 合并规则（daemon 每次画星后自动跑）

| 事件 | daemon 行为 |
|---|---|
| 新画一颗 ★ | 「本书待办」加一行 `★ 第 N 页`（空批注），你打的旧批注全保留 |
| 擦掉一颗 ★ | 该行移除；它下面你打过的批注**移到自由区顶端**（`（以下批注对应的待办已不在）`），不丢 |
| 你在卡片打字 | 下次重建时逐字保留（靠 `read_root_text` 读回 → 重建时写回） |
| 无任何变化 | 跳过，不重建（零 churn、零副本） |
| 你正在编辑卡片 | 20 秒内不动它，下次再合（防竞态） |

## 你可以在自由区里手动照 2.md 排卡片

daemon 只管「本书待办」区；`━━ 我的笔记（自由区）━━` 之后随你写。想套 2.md 的三段式，
自己在自由区用 Text 工具打这些小标题即可（daemon 原样保留）：

```
━━ 我的笔记（自由区）━━
【线索框】
  🔵 时间节点：
  🔴 核心实体：
【逻辑网】
  （手写连线更快，但手写不被 daemon 保留，重要结论建议也打字）
【标签锚点】
  系统 Tags（原生标签面板勾选）：
  软链接：[指向 -> ID: ]
```

### 章名 · 节名 这一栏的现状

- **当前**：待办行只填 `★ 第 N 页`（页号来自 .rm 页序）。
- **待接**：墨香从微信读书下载的书有章节目录（EPUB nav）+ 页↔章映射 → 可升级成
  `★ 第一章《…》· 第 N 页`（daemon 已预留 `stars=(页号, 章节标签)` 的标签位，接上映射即可）。
- 第三方导入的书 / 手绘笔记本没有可靠页↔章映射 → 保持只填页号。

### 硬约束（reMarkable 现实，别踩）

- **不支持跨文件超链接**：卡片里的「第 N 页」跳不进原书页，只能顶部搜索书名软跳。故一书一卡（文件内可翻页），不做跨书全局索引深链。
- **手写读不回**：卡片上的批注必须**打字**（Text 工具）才能跨重建存活；手写笔迹会被重建覆盖。
