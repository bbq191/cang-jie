# 《书名》- 总结卡片（B 模型实际生成格式）

> 这是 `wr-stars-daemon` **真机实际生成**的卡片结构（已端到端验证）。每本有 ★ 待办的书对应一份
> 可编辑笔记本，命名 `《书名》- 总结卡片`。daemon 每次画星后重生成：**你用 Text 工具打的字全部保留**，
> 只更新「本书待办」区的 ★ 行。手写笔迹不保（读不回，会被重建抹掉）——**要留的批注请用 Text 工具打字**。
>
> 模板设计与社区范式出处见《[PKM 白皮书](../../pkm/docs/reMarkablePKM白皮书.md)》§06。

---

## 卡片模板由书的原生 Tag 决定

**每个有 ★ 的页 = 卡片里独立的一张页**（一主题一卡，留整页给你打字）。这一页注入哪套模板骨架，
由**书的 reMarkable 原生标签**决定（系统标签面板打，无需键盘/JSON）：

| 你打的标签 | 用的模板 | 适用 |
|---|---|---|
| （不打） | **通用·原子卡** | 默认，任何书/语言 |
| `#原文`（或 `#英文`） | **原文·英文原版** | 读英文原著：句子挖掘 |
| `#悬疑`（或 `#推理`/`#侦探`） | **悬疑·推理** | 推理/悬疑小说 |
| `#科幻` | **科幻·世界观制衡** | 科幻/奇幻 |

**两级标签 = 星级粒度**：标签有文档级（整本书）和**页级**（`pageTags`，只这一页）两种。
- 整本书打 `#原文` → 全书每颗星都用原文模板；
- 某一页打页级 `#悬疑` → **只这一页**的星用悬疑模板；
- 两者叠加（整本 `#原文` + 反转页 `#悬疑`）→ **那颗星的模板 = 两套合并去重**（原句/生词… + 线索框/逻辑网…，共用的「🔗 关联」行合并成一条）。

> 词表保持精简——按上表这几个标签名打；不认识的标签（如 `#荐书`）自动忽略、退默认通用。

## 四套模板长什么样（daemon 自动注入的初始骨架）

冒号后 / 字段下**你用 Text 工具打字**，重建时逐字保留。首行 `[ID: …]` 是机器锚点（供 MOC 软链接检索）。

**① 通用·原子卡（默认）** —— 一卡一概念、概念导向、密集链接（Evergreen）
```
[ID: 第一章 - P 4]
🏷 概念（一卡一概念，起个能独立成立的名）：
📝 用我的话说清（费曼，勿抄原文）：
💡 SO WHAT · 我的洞见 / 解释了什么：
🔗 关联 → ID：
📚 出处：
```

**② 原文·英文原版（`#原文`）** —— 句子挖掘 + 深度词汇
```
[ID: … - P 4]
❝ 原句（含生词的完整句子 +页码）：
🔤 生词/短语 → 释义（英英优先，标词性/读音）：
🌐 我的理解 / 意译：
🗣 地道表达（可复用的说法，"偷"来自己用）：
❓ 没读懂 / 语法疑问：
🔗 关联 → ID：
```

**③ 悬疑·推理（`#悬疑`）** —— 线索 / 时间线 / 诡计逻辑
```
[ID: … - P 4]
〔线索框〕🔵 时间线 / 🔴 关键人物 / 🟢 案件·诡计代号：
〔逻辑推演网〕（手写树状+箭头：诡计拆解·破局链·伏笔）：
〔主题与金句〕🎯 主题 / 🟡 金句：
🔗 关联 → ID：
```

**④ 科幻·世界观制衡（`#科幻`）** —— 势力 / 权力 / 设定规则 / 冲突
```
[ID: … - P 4]
🏛 势力阵营（谁 vs 谁）：
⚖️ 权力/资源制衡（靠什么维系或打破）：
⚙️ 关键设定 / 技术规则：
🔥 核心冲突：
🎯 主题与我的洞见：
🔗 关联 → ID：
```

**组合示例**（整本 `#原文` + 某页 `#悬疑`，那颗星）：
```
[ID: … - P 4]
❝ 原句（含生词的完整句子 +页码）：
🔤 生词/短语 → 释义（英英优先，标词性/读音）：
🌐 我的理解 / 意译：
🗣 地道表达（可复用的说法，"偷"来自己用）：
❓ 没读懂 / 语法疑问：
〔线索框〕🔵 时间线 / 🔴 关键人物 / 🟢 案件·诡计代号：
〔逻辑推演网〕（手写树状+箭头：诡计拆解·破局链·伏笔）：
〔主题与金句〕🎯 主题 / 🟡 金句：
🔗 关联 → ID：          ← 两套共用，合并成一条
```

## 一张完整卡片（第一页带标题 + 待办区头）

```
《赎罪》- 总结卡片

━━ ★ 本书待办 ━━
★ 洋娃娃 · 第 8 页          ← 章名·页号自动填（EPUB 读 .epubindex + toc；含节名则「章 - 节」）
[ID: 洋娃娃 - P 8]          ← 机器锚点（MOC 软链接 + 死链体检的键）
🏷 概念（一卡一概念…）：       ← 无标签 → 通用模板
…

（第 2 张卡片页 = 第二处 ★，同法按其页的标签选模板）
```

> 一星一页、**无自由区页**。擦掉某颗 ★ → 该卡片页连同你在上面打的字一起消失
> （star = 待办本身，擦星即完成）。开书不会重复生成，每本书恒 1 张卡。

## 合并规则（daemon 每次画星后自动跑）

| 事件 | daemon 行为 |
|---|---|
| 新画一颗 ★ | 加一张卡片页，按该星页的标签注入模板骨架（空批注） |
| 擦掉一颗 ★ | 该卡片页连同其批注一起消失（star = 待办本身） |
| 你在卡片打字 | 下次重建逐字保留（靠 `read_root_text` 读回 → 重建时写回） |
| 老星 + 新标签 | **不改老星**（其批注原样保留）；换模板只对**新画的星**生效（forward-only） |
| 无任何变化 | 跳过，不重建（零 churn、零副本） |
| 你正在编辑卡片 | 20 秒内不动它，下次再合（防竞态） |

## 顺带：全库死链体检

daemon 另生成一本只读的 **「🔗 卡片索引 · MOC 死链体检」** 笔记本：列出全库所有 `[ID:]` 锚点 +
指向不存在锚点的死链。你在 MOC 里删了卡、留下死链，这里会标出来（勿在此本手写，重建会覆盖）。

## 硬约束（reMarkable 现实，别踩）

- **不支持跨文件超链接**：卡片里的「第 N 页」跳不进原书页，只能顶部搜索软跳。故一书一卡（文件内可翻页），不做跨书深链。
- **手写读不回**：批注必须**打字**（Text 工具）才能跨重建存活；手写笔迹会被重建覆盖。
- **锚点 forward-only**：`[ID: … - P N]` 格式（及无章节书的书名前缀）只对新卡生效，旧卡不改，库内新旧并存（死链体检按字面串比对不受影响）。
